# Anvaya V1 — release scope

Date: 2026-11-03 · Owner: PritBlitz · Status: in progress (target 2026-11-05)

This file defines what V1 ships. It does not redefine the product: `docs/PRD.md`, `docs/ROADMAP.md`
and the other canonical documents stay the source of truth. V1 covers every PRD requirement and every
ROADMAP phase (0–8), plus the "team and enterprise" and "advanced intelligence" capabilities, except
where this file says otherwise.

## Decisions (2026-11-03)

| Area | Decision |
|---|---|
| AWS (Phase 8) | Infrastructure as code only (Terraform, validated, never applied). The reproducible deployment that is actually exercised is a local production-like Docker Compose stack with health checks and a tested rollback. |
| Production execution plane (SECURITY §7) | Add a gVisor (`runsc`) sandbox driver, allowed in production; Firecracker on AWS is documented as the deployment target. The Docker driver stays development-only. |
| GitLab / Bitbucket | Out of V1. The provider boundary stays GitHub-first (FR-GIT-001). |
| Orchestration | Explicit persisted state machine, not LangGraph (ADR-0001). |
| Repository reconnection across workspaces | Follow-up (backend tracker B-10); the one-workspace-per-repository rule in DATABASE.md stands for V1. |

## Work packages

### A. Remaining PRD requirements
- FR-WF-001 / FR-GIT-006: tasks from a GitHub pull request and from a failing check run, besides manual and issue tasks.
- FR-OBS-004: admin-configurable quotas (per-workspace daily token and run quotas) and concurrency limits (max active runs).

### B. Team, enterprise and advanced intelligence (ROADMAP §2)
- Workflow templates (bug fix, add tests, refactor, dependency upgrade, migration plan).
- Multi-provider support: a second, opt-in hosted provider behind the existing adapter, with the same disclosure and no-silent-fallback rules.
- Call graph, change-impact prediction and test selection from parsed symbols and imports.
- Cross-repository knowledge search within a workspace.
- Migration planning workflow (plan-only, evidence-backed).

### C. Hardening, evaluation and release (ROADMAP phases 7–8)
- gVisor sandbox driver with policy tests.
- Retrieval and workflow benchmarks with documented methodology and results (`docs/evaluations/`).
- A dedicated security test suite (tenant isolation, CSRF, webhook signatures, prompt injection, sandbox escape attempts, SSRF/redirect, secret redaction).
- Backup/recovery and incident runbooks (`docs/runbooks/`), with a tested backup and restore.
- CI/CD for web, API and AI service; environment separation (development, test, production config).
- Terraform for the AWS reference deployment (`infra/aws/`).
- Local production-like deployment with health checks and a tested rollback.
- Shared contracts package (`packages/contracts`), root `.env.example`, Firefox and WebKit E2E.
- Demo repository walkthrough, architecture case study, known limitations.

## Exit criteria

ROADMAP §6 definition of done for each capability, plus Phase 8: reproducible deployment, health
checks and rollback tested, an end-to-end demo that ends in a human-approved PR, and documentation
that matches behaviour. Live model and live GitHub checks are labelled separately and are not
required for CI (CLAUDE.md §12).
